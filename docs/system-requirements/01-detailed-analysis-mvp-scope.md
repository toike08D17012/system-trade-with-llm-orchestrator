## 1. 目的

人間が指定した1銘柄を、初期共通証拠と独立Web探索を使うCodex系・Claude系の分析へ渡す。
各系統が発見した候補資料を検証・共通化したうえで、中期・長期の投資仮説と、
エントリー・撤退判断の参考情報を、レビュー可能なMarkdown・JSONレポートへまとめる
詳細解析MVPの境界を定める。

## 2. MVP入力と実行時設定

### 2.1 必須タスク項目

<!-- markdownlint-disable MD013 -->

| 項目 | ドラフト要件 |
| --- | --- |
| 銘柄数 | 1タスクにつき1銘柄 |
| 銘柄識別 | ティッカーだけでなく、市場を一意に示すMICまたは同等の市場識別子を必須とする |
| 対象市場 | 日本株または米国株。1タスクにつき1市場とし、最初に実装する市場は承認前に1つ選ぶ |
| 投資評価期間 | `medium_term`（12か月以上24か月未満）と`long_term`（24か月以上60か月以下）を、同じ共通証拠から両方分析する |
| 調査基準時刻 | `as_of_cutoff` はタスク受付時の現在時刻からシステムが生成し、同一タスク内で固定する。利用者入力にはしない |
| 市場時間設定 | 対象市場について承認済みのIANAタイムゾーンと取引カレンダーを適用する |
| 評価Policy Version | 適用した評価方針の版を必須とする |

<!-- markdownlint-enable MD013 -->

名称、通貨、セクターなど、入力識別後に確定する属性はデータ準備段階で検証する。
入力スキーマ、列挙値、エラー形式はP1で定義する。

通常のMVP実行では、利用者に単一の投資評価期間を必須指定させない。中期・長期の
分析に必要な証拠を一度だけ準備し、期間ごとに投資仮説、反証、主要リスク、監視条件、
評価可否、4段階評価を分けて出力する。期間横断の要約は作成するが、異なる期間の評価を
単一の4段階評価へ統合しない。

特定期間への絞り込みを利用者入力、限定再調査、または再出力で許可する場合の条件は
P1で定義する。絞り込み指定がないことを入力エラーにしてはならない。

`as_of_cutoff` は、データの取得時刻ではなく、分析で利用可能とみなす情報の締切時刻で
ある。タスク受付時にシステムが現在時刻をUTCオフセット付きRFC 3339形式で固定し、
同じ `task_id` のデータ準備、独立分析、レビュー、再調査、再開を通じて変更しない。
その時刻以下に初めて公衆が利用可能になった情報だけを判断材料にする。

通常のMVP実行では、利用者による過去・未来の `as_of_cutoff` 指定と日付だけの指定を
受け付けない。過去時点の解析は、承認済みのpoint-in-timeデータまたは固定fixtureを使う
評価モードに限定し、通常のMVP実行範囲外とする。公表時刻または初回利用可能時刻を
確認できない情報は、将来情報が混入しない保守的な規則を適用できる場合だけ使用する。

市場のIANAタイムゾーンと取引カレンダーは、直近完了取引日、価格観測時刻、休場日、
同日時間外公表を解釈するために使う。これらから `as_of_cutoff` を導出しない。

### 2.2 入力検証

- 銘柄数、市場識別子、システムが固定した `as_of_cutoff`、市場時間設定を
  分析開始前に検証する。
- 投資評価期間を絞り込む任意指定を受け付ける場合は、承認済みの期間だけを許可し、
  指定がない場合は `medium_term` と `long_term` の両方を適用する。
- 利用者入力に `as_of_cutoff` が含まれる場合は、通常のMVP実行として受け付けない。
- 銘柄を一意に解決できない場合は推測せず、入力修正待ちにする。
- `as_of_cutoff` より後に初めて利用可能になった情報を通常分析へ混入させない。
- 将来情報の混入が判明した場合は、対象成果物を無効として再生成する。

## 3. MVP境界

```mermaid
flowchart LR
    H[人間が1銘柄を指定] --> D[初期共通証拠の準備と検証]
    D --> W[Codex・Claudeが独立に<br/>Web探索と初回分析]
    W --> V[候補資料の検証と<br/>共通証拠への統合]
    V --> W2[共通追加証拠で<br/>影響範囲を独立再分析]
    W2 --> R[統合と一次レビュー]
    R --> A[必要時だけ限定再調査・追加監査]
    A --> F[Markdown・JSONレポート]
```

MVPに含めるものは次のとおりとする。

- 指定銘柄の検証済み証拠データ準備
- 日本株を対象とする場合のUSD/JPY日次時系列の準備と、円建て株価から
  ドル換算の価格推移・リターンを算出する決定論的処理
- Codex系作業者1つとClaude系作業者1つによる、中期・長期それぞれの独立した総合分析
- Codex系・Claude系が互いの検索結果と暫定結論を見ずに行う独立Web探索
- Agentが発見した候補資料の取得・検証と、有効な資料の和集合を共通証拠として
  両作業者へ差し戻す証拠収束
- オーケストレーター、一次レビューワー、Antigravityを含む各Agentが、担当処理で
  情報不足を認識した場合に行う追加Web検索
- 現在の価格状況に基づくエントリー・撤退判断の参考情報
- 統合、一次レビュー、限定再調査、条件付き追加監査
- 人間判断待ちを含む安全停止
- 根拠、反証、欠損、不一致を追跡できる最終レポート

MVPに含めないものは次のとおりとする。

- 一次スクリーニング対象となる銘柄一覧（Universe）の取得・作成と、その一覧に対する自動一次スクリーニング
- 一次スクリーニング後のLLM簡易調査
- 証券会社接続、注文送信、自動売買、最終投資判断の自動化
- 自動通知、定期実行、通常作業者の専門分割、モデル数の増加
- 現在のWebから任意の過去時点を再構成する解析
- 短期的な株価上昇・下落の方向予測と、それに対する合格・不合格判定
- 特定価格での購入・売却・損切りの指示と、ポジションサイズの決定
- 複数銘柄を同一の詳細解析タスクで扱うこと
- 完了済みの銘柄別分析を再入力とする銘柄間比較・ランキング

指定銘柄は一次スクリーニングを通過したものとして扱わない。詳細解析MVPは、
人間が指定した銘柄を同じ入口から受け付けるだけであり、候補選定理由を生成しない。

## 4. 5観点の分析要件

<!-- markdownlint-disable MD013 -->

| 観点 | MVPで必要な入力 | 評価方針 |
| --- | --- | --- |
| 財務 | 損益、貸借、キャッシュフロー、主要KPI、会計期間、通貨・単位 | 成長性、収益性、財務健全性、キャッシュ創出力、異常・継続性を分け、中期・長期への影響を評価する |
| バリュエーション | 時点整合した株価、株式数、企業価値入力、過去値、比較対象 | 過去・同業比較と前提感応度を示し、中期・長期で前提または結論が異なる場合は分けて示す |
| 事業 | 開示資料、事業区分、市場・競争、経営方針、主要リスク、重要な為替エクスポージャーとヘッジ方針 | 事実、推論、将来仮説を分離し、中期・長期それぞれの成長要因と仮説崩壊条件を対で示す |
| テクニカル・売買判断参考 | 時点整合した日次価格・出来高、調整方法、計算ロジック版、確認可能な重要イベント、日本株では時点整合したUSD/JPYとドル換算系列 | 現在のトレンド、変動性、過熱感、支持・抵抗候補、エントリー参考条件、価格上の撤退参考条件を補助情報として示す。円建てとドル換算の推移が異なる場合は区別する |
| リスク・反証 | 弱気材料、欠損、出典不一致、イベント、各観点の反証条件 | 強気仮説を期間ごとに独立して反証し、重大リスク、監視条件、投資仮説上の撤退条件、評価不能事項を明示する |

<!-- markdownlint-enable MD013 -->

エントリー・撤退判断の参考情報は、短期的な値上がりを予測する独立の投資評価ではない。
価格上の撤退参考条件と、中期・長期の投資仮説が成立しなくなる条件を分けて示す。
価格帯や条件を示す場合は、使用した価格時点、計算根拠、前提、イベントリスクを追跡可能にし、
特定価格での売買または損切りを指示しない。最終的なエントリー、許容損失、撤退、売買の
判断は人間が行う。

日本株の正式な株価系列とバリュエーション入力は上場通貨である円建てを使用する。
ドル換算系列は、為替ヘッジを行わないドル投資家から見た価格推移を確認する補助情報とし、
円建て株価を置き換えない。USD/JPYを1米ドル当たりの円として、同一または直前の承認済み
観測時点へ揃えた値から、ドル換算株価を `円建て株価 / USD/JPY` で計算する。使用した
株価、為替、観測時刻、計算ロジック版を追跡可能にする。

ドル換算系列だけから、発行体の業績に対する為替感応度や外国人投資家の売買動向を推定しない。
業績への影響は、売上・費用・資産・負債の通貨構成、発行体開示の為替感応度、ヘッジ方針などの
別証拠で評価する。USD/JPYを取得できない場合は欠損を明示してドル換算の主張を確定しない。
適用Policyがその主張を必須とする場合だけ、影響を受ける観点または評価期間を
`not_evaluable` とし、銘柄全体を自動的に評価不能にしない。

重要な数値と主張は、出典、取得日時、対象期間、`evidence_id` まで追跡できなければ
最終レポートへ確定情報として掲載しない。

有効な `evidence_id` は、`manifest` 内で一意に解決でき、保存内容または承認済みの
外部参照のハッシュと一致し、ソース承認と `as_of_cutoff` の検証に成功したものとする。
P1では主張ごとにID、種別、重要度、証拠参照を持つ契約を定義する。

## 5. 評価と実行状態の分離

銘柄の後段評価は、`medium_term` と `long_term` の投資評価期間ごとに次の4段階とする。

| 評価 | 意味 |
| --- | --- |
| 合格 | 現在の証拠とPolicyで主要条件を満たし、重大な未解決事項がない |
| 条件付き合格 | 主要条件をおおむね満たすが、明示した条件・欠損・監視事項が残る |
| 再調査 | 判断に必要な証拠または検証が不足し、限定再調査で解消可能である |
| 不合格 | Policy上の重要条件を満たさない、または反証により仮説を維持できない |

4段階評価とは別に、評価可否を投資評価期間ごとに `evaluable` または
`not_evaluable` として保存する。
必須証拠が不足していても上限内の限定再調査で解消可能な場合は、`evaluable` の
`再調査` とする。取得不能、利用条件違反、または限定再調査の上限到達により必須証拠を
確保できない場合は `not_evaluable` とし、4段階評価を未設定にする。`not_evaluable` を
`条件付き合格`、`不合格`、または一次スクリーニングの `NOT_EVALUABLE` へ自動変換しない。

期間別の評価可否と4段階評価は、`実行中`、`追加監査中`、`人間判断待ち`、`失敗`、`中断`、
`利用上限到達` などの実行状態とは別に保存する。解析が完了していない場合、
4段階評価を確定値として外部へ提示しない。

MVPでは、Agentの分析、合議、または再レビューの途中でトークン利用枠へ到達することを
許容する。この場合は`利用上限到達`として中間成果物と未処理事項を保存し、未完了出力を
完成した分析またはレビューとして採用しない。利用上限到達だけを理由に評価可否を
`not_evaluable`へ変更せず、プロンプト、コンテキスト配分、モデル設定、契約プラン、
回数上限の見直しは実測結果に基づいて人間が判断する。

対象銘柄の機械可読結果は、合格、不合格、評価不能を含めて保存する。人間向けレポートには
中期・長期の評価を併記し、一方が `不合格` または `not_evaluable` の場合も省略せず、
理由、欠損、反証を示す。`再調査` は未完了として扱い、解消または上限到達まで
該当期間の評価を最終化しない。

期間横断の要約では、中期・長期の一致点と相違点、現在の価格状況、エントリー参考条件、
価格上の撤退参考条件、投資仮説上の撤退条件を簡潔に示す。期間横断の要約自体には、
別の4段階評価を付与しない。

## 6. 成功条件

次は承認候補となる初期目標であり、固定fixtureと許可された試行で測定する。

| 分類 | ドラフト成功条件 |
| --- | --- |
| 人間が確認する銘柄数 | 1タスク1銘柄とする |
| レポート量 | 編集SLO。期間別評価とエントリー・撤退参考情報を含め、要約10件、各観点5項目、本文4,000字程度を初期目安とする |
| 調査時間 | 1銘柄タスクの開始から解析完了・レビュー可能状態までの初期SLOを、試行結果に基づいて承認する。ハードタイムアウトは別に定める |
| 証拠追跡性 | 解析完了時に、最終レポートの重要な数値・事実主張の100%に有効な `evidence_id` がある |
| 品質 | 最終化時に未解決の `critical` または `high` の一次レビュー指摘が0件である |
| 不確実性 | 欠損、出典不一致、モデル間不一致、反証条件が非表示のまま最終化されない |
| 再現可能性 | 全量保持した入力、証拠、設定、成果物から処理を再構成できる |
| コスト | 権威ある実測値と推定値を区別して使用量を記録し、呼び出し前の予約を含む承認済み方式でハード上限を超えない |
| 安全 | 証券会社へ接続せず、秘密情報や外部資料内の命令をAgent指示として扱わない |

金額ベースのタスク上限は、採用データソースとモデルが決まった時点で承認する。
金額上限が未設定のまま実ネットワーク・実CLIを使うMVP評価を開始してはならない。

## 7. 承認前の未決定事項

- 最初に対応する市場
- 投資評価期間の任意絞り込みを許可する実行種別と入力契約
- エントリー参考条件と価格上の撤退参考条件の算出・提示ルール
- 現行の価格・出来高・ニュースの粒度と鮮度が売買判断の参考情報に十分か
- USD/JPYの採用データソース、観測価格種別、株価との時点整合規則
- タスク受付時刻を確定する処理境界と時計同期の要件
- 市場ごとの直近完了取引日、価格観測時刻、同日時間外公表の扱い
- 1銘柄タスクの調査時間SLOを決める試行条件
- 調査時間SLOより長く、終了処理の余裕を持つハードタイムアウト
- 期間別評価と売買判断の参考情報を含めた本文4,000字程度という上限目安の妥当性
- タスク単位の金額、トークン、外部API呼び出し上限
- 独立Web探索の検索範囲、記録項目、証拠収束回数、検索・再分析の利用上限

## 8. 将来の銘柄間比較との境界

業界などで候補を絞り込んだ後に、同業他社の複数銘柄を比較するワークフローは、
詳細解析MVPの後続拡張候補とする。比較のために、複数銘柄の証拠と暫定結論を
1つの通常作業者セッションへ混在させない。

将来の比較ワークフローでは、銘柄ごとの詳細解析を独立したタスクとセッションで完了し、
構造化済みの銘柄別分析結果を比較タスクへの入力とする。比較作業者が相対的な強み、弱み、
バリュエーション、主要リスク、比較不能事項を整理した後、オーケストレーターが結果を統合し、
必要なレビューを経て比較結果を確定する。

この拡張に備え、MVPの銘柄別分析結果には、少なくとも `task_id`、銘柄識別子、
`as_of_cutoff`、評価Policy Version、期間別評価、重要な主張と `evidence_id` を保持する。
比較タスクの入力・出力、比較グループ、状態遷移、利用上限、権限、レビュー、監査の詳細契約は、
比較機能を実装するリリースの承認済み要件として別途定義する。

個別銘柄のバリュエーションで行う過去・同業比較は、承認済みの比較対象データを証拠として
使用する分析であり、複数の詳細解析結果を統合する銘柄間比較タスクとは区別する。
