## 1. 目的

詳細解析MVPのモデル配置、独立性、一次レビュー、限定再調査、争点分類、
Antigravity追加監査、監査結果の適用、人間へのエスカレーションを定める。

## 2. モデル配置

| 役割 | ドラフト要件 |
| --- | --- |
| オーケストレーター | Codex系またはClaude系から設定で1つ選び、実際のモデルと設定を記録する |
| 通常作業者 | Codex系1つ、Claude系1つを使用する |
| 一次レビューワー | 各実行に1つ割り当て、オーケストレーターと異なるモデル系統にする |
| 条件付き第三者監査 | Antigravityを重要な未解決争点にだけ使用する |

特定のモデル名を要件へ固定しない。利用可能性、構造化出力、コンテキスト長、
費用、安全設定を確認して設定ファイルで選び、実際に利用したモデル、版、論理設定、
製品固有設定を`manifest`へ記録する。

## 3. 独立性

- Codex系とClaude系の作業者へ、同じ指定銘柄、調査条件、共通証拠、評価Policyを渡す。
- 独立分析が完了するまで、他作業者、オーケストレーター、レビューワーの暫定結論を渡さない。
- 各作業者は証拠外の事実を補わず、事実、推論、仮説、欠損、反証条件を区別する。
- 統合時に不一致を多数決、平均、モデル権威によって消さない。
- 一次レビューワーへは統合結果と根拠を渡すが、望ましい合否を指示しない。
- Antigravityへは作成主体を匿名化した争点パケットだけを渡す。

## 4. 一次レビュー

一次レビューは、少なくとも次を確認する。

- 重要な数値・事実主張に有効な証拠参照がある。
- 事実、推論、仮説、評価が混同されていない。
- 5観点、重要リスク、反証条件、欠損、モデル間不一致が扱われている。
- `as_of_cutoff`、初回利用可能時刻、対象期間、鮮度、通貨、単位が整合している。
- 評価Policyの適用と4段階評価の理由が整合している。
- 出力スキーマと安全境界に違反していない。

次をすべて満たす場合だけ一次レビュー合格とする。

1. 構造化出力と証拠参照の検証が成功している。
2. `critical` または `high` の未解決指摘がない。
3. `medium` 以下の未解決指摘は最終評価へ重大な影響を与えず、残置理由が記録されている。
4. 再調査または争点化が必要な指摘の処理が完了している。
5. レビューワーと異なる処理を採用した場合、その理由とPolicyが記録されている。

指摘ごとに、受け入れ、限定再調査、不採用、争点化のいずれかと理由を保存する。
すべての指摘IDは、解析完了前に重複なく1つの終端処理へ到達しなければならない。

指摘の重要度は次の基準で判定する。

| 重要度 | 基準 |
| --- | --- |
| `critical` | 安全境界、秘密情報、利用規約、将来情報の混入、または成果物全体の有効性を損なう |
| `high` | 4段階評価、評価可否、主要仮説、重大リスク、重要な数値・事実主張が変わり得る |
| `medium` | 結論を直ちに変えないが、説明、欠損、不確実性、証拠対応の重要な修正を要する |
| `low` | 意味を変えない表記、構成、または軽微な明確化である |

重要度は文体やモデルの確信度ではなく、修正しない場合の影響で決める。

## 5. 限定再調査

- 再調査は、指摘または争点の解消に必要な証拠・主張へ対象を限定する。
- MVPでは1銘柄につき1回の再調査バッチを上限候補とする。
- 再調査後は、影響を受けた主張、評価、レビュー指摘だけを再評価する。
- 再調査後の再レビューは最大1回とし、追加の調査ループを自動起動しない。
- 上限後も重要事項が未解決なら、条件を満たす争点だけ追加監査へ送り、
  それ以外は人間判断待ちまたは `not_evaluable` にする。

## 6. 争点分類と重要度

| 分類 | 通常の処理 | 追加監査候補 |
| --- | --- | --- |
| 事実誤認 | 元データ照合または限定再調査 | いいえ |
| 根拠不足 | データ取得、`not_evaluable`、限定再調査 | いいえ |
| スキーマ・形式違反 | 機械検証と修正再出力 | いいえ |
| 評価基準の適用差 | Policy照合 | 解消せず影響が重大な場合 |
| 論理的な飛躍 | 推論と証拠の再構成 | 解消せず影響が重大な場合 |
| 将来仮説の相違 | 前提と反証条件の明示 | 影響が重大な場合 |
| リスク重要度の相違 | 共通基準で再評価 | 影響が重大な場合 |
| 文体・表現 | 通常修正 | いいえ |

`material` は、争点の解決方向によって4段階評価、主要投資仮説、重大リスク、
または人間の最終判断材料が変わり得る状態とする。

## 7. Antigravity追加監査の起動条件

次をすべて満たす場合だけ起動する。

1. 一次レビュー、指摘応答、許可された限定再調査が完了している。
2. 双方の主張と根拠を持つ未解決争点がある。
3. 事実確認またはスキーマ修正だけでは解消できない。
4. 最終結果への影響が`material`である。
5. 匿名化した中立な争点パケットを構成・検証できる。
6. 時間、トークン、金額、回数の上限内である。
7. 同じ争点をAntigravityで監査済みではない。

MVPでは、1タスクにつきAntigravityの論理監査を最大1回とし、1つの銘柄に属する
最大3争点を1つの監査セッションへまとめる案を採用候補とする。異なる銘柄の争点を
同じ監査セッションへ混在させない。監査対象に選ばれなかった別銘柄の `material` な
争点は、人間判断待ちとする。各争点の論理監査は1回限りとする。

起動失敗またはスキーマ修正を含む物理的なCLI実行は、初回を含めて最大2回とし、
別々の再試行枠として加算しない。正確な計数単位と上限は承認前に確定する。

Antigravityは通常作業者、常設レビューワー、単純多数決の第三票として使用しない。
Codex系またはClaude系の追加セッションを第三者監査の代替として表示しない。

## 8. 監査の実行境界

- 読み取り専用の争点専用ワークスペースを使う。
- 対象争点、適用Policy、その争点に必要で外部処理が承認済みの共通証拠だけを渡す。
- リポジトリ全体、他銘柄、作成主体名、会話履歴へアクセスさせない。
- 外部Web検索、ファイル更新、シェル実行を既定で無効にする。
- 追加証拠が必要な場合は、監査内で取得せず要求として返す。
- 出力をスキーマ検証し、争点外の結論や無出典の新規事実を採用しない。

## 9. 監査結果の適用決定表

| 監査結果 | 証拠状態 | 原則的な処理 |
| --- | --- | --- |
| AまたはBを支持 | 既存証拠で十分 | 支持理由とPolicy適用を検証し、該当案を採用または修正する |
| どちらも支持しない | 両者に修正余地 | 両案を修正し、条件付き合格、不合格、人間判断待ちのいずれかへ進む |
| 判断不能 | 追加証拠を取得可能 | 上限内なら限定再調査。上限到達後は人間判断待ち |
| 判断不能 | 追加証拠を取得不能 | 人間判断待ち。人間が明示的に処理するか、`material` でないと再判定するまで評価を確定しない |
| 人間判断を推奨 | 価値判断・方針判断が必要 | 両論と証拠を添えて人間へエスカレーションする |
| スキーマ不正・実行失敗 | 監査結果を利用不能 | 同じ設定で1回だけ再実行し、失敗時は人間判断待ち |

監査結果は拘束的な最終判定ではない。異なる処理を採用する場合は、理由、証拠、
適用Policyを記録し、差異が重大なら人間へエスカレーションする。

## 10. 人間へのエスカレーションと最終化

通常処理が完了し、未解決の重大事項がない場合は、機械可読な解析結果を
`解析完了` として固定できる。`解析完了` と、人間向け成果物を
`reports/finalized-reports/` へ移送する `最終化` は別の状態とする。
最終化には、権限を持つ人間の承認記録と、解析完了成果物のハッシュ一致を必要とする。

次の場合は `解析完了` へ自動遷移せず、人間判断待ちとする。

- 追加監査後も`material`な争点が解消しない。
- 重要な証拠が欠損または不一致で、承認済みPolicyだけでは `not_evaluable` を含む
  処理を一意に決められない。
- Policy、利用規約、安全境界の適用に人間の判断が必要である。
- モデル系統の独立性または必要な役割数を満たせない。
- 利用上限、認証失敗、外部サービス停止により必要工程を完了できない。
- 監査結果とオーケストレーターの処理が重大に異なる。

人間には、争点、両論、共通証拠、レビュー履歴、監査結果、未決定事項、
選択可能な次状態を提示する。人間の決定者、日時、理由を記録する。

## 11. 評価と実行状態

銘柄評価の4段階と評価可否は
[詳細解析MVPの範囲と成功条件](01-detailed-analysis-mvp-scope.md#5-評価と実行状態の分離)
に従う。実行状態は別概念として、少なくとも次を識別する。

- 受付・データ準備・分析・統合・一次レビュー・指摘解決
- 限定再調査・追加監査・人間判断待ち
- 解析完了・最終化・中断・取消・失敗・利用上限到達

状態ID、遷移条件、再開可能点、無効遷移はP1の契約で定義する。

## 12. 承認前の未決定事項

- 1銘柄1再調査バッチと再レビュー最大1回の上限
- 1タスク1論理監査、単一銘柄の最大3争点、物理実行最大2回という上限
- `medium` 指摘を残したまま合格できる例外条件
- 人間判断を入力できる役割と承認権限
