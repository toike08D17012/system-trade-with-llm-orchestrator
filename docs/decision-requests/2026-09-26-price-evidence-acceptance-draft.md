# 日次価格証拠の受入条件（承認済み）

状態: Approved。2026-09-26、リポジトリ所有者が本ドラフトを承認した。
カレンダーと月末後の上場変更の扱いを含め、以下を価格証拠の受入方針として採用する。
関連要件と固定期間の内部受入API・CLIへ反映済み。既存成果物の判定は変更しない。
参照を維持するため、ファイル名の`draft`は変更していない。

## 1. 目的と対象

東証内国現物株1銘柄の日次価格証拠について、後続の計算・分析へ渡せる条件を定める。
価格証拠の受入と、財務・為替・開示等を含む詳細解析全体の開始可否を区別する。

初期対象は、JPX一覧で識別した銘柄の円建て日次OHLC、調整済み終値、出来高、配当、株式分割とする。
受入は提供値の来歴・構造・整合性を確認したことを意味し、他社データとの一致や価格値の絶対的な正しさを保証しない。

## 2. 委任された事項の扱い

### 取引日カレンダー

初期運用は、JPXの現物市場休業日規則と内閣府の公表祝日・休日に基づく、出典付きの
ローカル予定取引日カレンダーを使う。自動取得サービスや毎実行時の取得は必須にしない。
対象期間全体を含むこと、出典・確認日・算出規則・内容hashを保持することを条件とする。
単なる平日一覧への置換は認めない。

臨時休場を毎回網羅的に調べることは受入の必須条件にしない。
日付差分がある場合、または休場を示す情報が見つかった場合だけ根拠を追加し、
カレンダーを別版として更新する。価格の欠落を消す目的で取引日を削除しない。
差分の理由が解決するまでは受入を保留する。

この方針で、既存の出典付き調査カレンダーを初期の照合入力として採用する。
新しいネットワーク取得経路、外部配布や追加の利用権限を許可するものではない。

### 月末後の上場変更

初期運用では、利用する月次JPX一覧の基準日時点で対象銘柄が適格であることを必須とする。
一覧の基準日と、最新掲載月を確認できている場合はその確認日を記録する。
毎実行時の掲載ページ再取得や、月末後の変更を網羅的に追跡する仕組みは必須にしない。

月次資料の更新確認は月次運用で行い、未確認や更新待ちは制約として表示する。
現在の上場適格性を未確認のまま、月次一覧の時点情報として価格証拠を受け入れられるものとする。
ただし、取得済みの情報から上場廃止・対象外市場への移行・銘柄取り違えなどの矛盾が判明した場合は保留する。
既知の矛盾を「未確認」の扱いで無視しない。

## 3. 必須の受入条件

以下をすべて満たす場合に、指定した対象期間の価格証拠を受け入れる。

| ID | 条件 | 確認方法 |
| --- | --- | --- |
| PA-01 | 銘柄が一意である | 証券コードと`XTKS`、JPX snapshotの適格性、取得symbolの対応が一致する |
| PA-02 | 取得元・取得方法が許容範囲内である | 既存のsource承認と利用範囲に適合し、provider・ライブラリ版・関数・引数・取得時刻を保持する |
| PA-03 | 最低3暦年を対象とする | 対象期間を明示し、その全期間の予定取引日が揃う。要求期間が3年というだけでは合格にしない |
| PA-04 | 日付が整合する | 東京日付で整列・重複なし・範囲外なし。出典付きカレンダーに対する欠落・余剰がない |
| PA-05 | 必須数値が有効である | OHLC・調整済み終値・出来高・配当・分割に欠損・非有限値がなく、符号・整数性・OHLC大小関係が妥当である |
| PA-06 | 通貨と時間基準が確認できる | 価格通貨`JPY`と`Asia/Tokyo`を取得メタデータから確認し、symbolだけで推定しない |
| PA-07 | 調整とactionの意味が明示される | 調整前OHLC、providerの調整済み終値、配当・分割の提供値を区別し、未提供の調整済みOHLCを作らない |
| PA-08 | 保存した証拠を追跡・再検証できる | 原取得表、出典、正規化データ、JPX一覧、カレンダー、参照hash、検証結果と判定版が対応する |
| PA-09 | 既知の重大な矛盾がない | 銘柄・市場・通貨・日付・数値・来歴の未解決の矛盾が残っていない |

PA-05では、価格は正、出来高は0以上の整数、配当と分割は0以上とする。
分割の0はproviderの「イベントなし」として保持する。異常値を丸め・補間・削除して合格へ変えない。
大幅な値動きだけでは不正値と断定せず、確認で矛盾が見つかった場合に保留する。

3暦年の境界は、対象期間の排他的な終了日から3年前を開始日とし、うるう日は既存の境界処理に従う。
通常実行で使用するときは、証拠凍結時点の直近完了取引日まで含むことを別途確認する。
過去の固定期間の受入結果を、新しい実行でそのまま「最新」とみなさない。
当日分が未検証なら当日を完了取引日と主張せず、採用した基準日と時点差を記録する。

## 4. 明示すれば受入を妨げない制約

| 制約 | 後続処理での扱い |
| --- | --- |
| 現在の上場適格性・最新掲載月の再確認が未完了 | 一覧の基準日と確認範囲を表示する。現在適格との断定はしない |
| 臨時休場・個別売買停止の網羅的な調査が未実施 | 予定取引日との一致として報告する。既知の日付差分は免除しない |
| Yahooの原HTTP本文を保存していない | 承認済み標準history経路の戻り表を原取得表として識別する |
| 調整済みOHLCがなく、調整済み終値だけがある | 調整済みOHLCを必要とする計算へ渡さない |
| 配当ごとの原通貨を独立検証していない | 提供値を保持する。配当再投資・総収益等の計算で必要なら、その計算を保留して追加確認する |
| 別providerとの価格照合をしていない | 独立照合済みと記載しない |

これらは価格証拠の受入範囲に限った許容事項である。
後続の計算が必要とする入力を欠く場合、その計算の実行可否を別に判定する。

## 5. 判定結果と保存

次の状態名は承認された要件であり、固定期間の内部受入API・CLIへ反映済みである。

| 結果 | 意味 |
| --- | --- |
| `accepted` | 必須条件を満たし、上記の制約も残っていない |
| `accepted_with_limitations` | 必須条件を満たすが、許容される制約が残る。制約と禁止する用途を列挙する |
| `pending` | 必須条件の不足・不一致により、価格証拠の受入を保留する。理由と再確認対象を記録する |

通信・読込・保存失敗は技術エラーとして別に記録し、銘柄の評価不可や受入成功へ変換しない。
新しい判定は元成果物を上書きせず、入力hash、対象期間、判定日時、受入方針版、
元taskの評価方針版、条件ごとの結果、制約を持つ別記録として保存する。
旧索引の`price_quality_passed=false`や未確認issueは当時の結果として保持する。

価格証拠の受入だけで`analysis_ready=true`にしない。
財務・為替・開示等の必須証拠、共通証拠集合の凍結、解析開始条件は既存要件に従う。

## 7. 要件への反映箇所と検証例

承認に基づき、以下の要件文書と固定期間の判定コードへ価格証拠の受入範囲を反映した。
既存要件の必須財務・為替・開示や、詳細解析完了前の鮮度確認は緩和しない。

- [データソースと証拠の方針](../system-requirements/02-data-source-and-evidence-policy.md):
  第5節に価格証拠の必須条件と許容制約、第6節に受入記録と来歴の扱いを追加した。
- [詳細解析MVPスコープ](../system-requirements/01-detailed-analysis-mvp-scope.md):
  予定取引日カレンダーの採用範囲と、銘柄の適格性を確認した基準日の扱いを明記した。
- 受入API・CLI・内部モデル: 承認済み実装計画に基づき、`preparation.price_acceptance`と
  `preparation.price_acceptance_cli`へ実装した。通常実行への接続は後続作業とする。

実装時には、最低限次を検証する。

| ケース | 期待結果 |
| --- | --- |
| 3年の日付・数値・来歴は正常で、現在の上場適格性だけ未確認 | `accepted_with_limitations` |
| カレンダーの対象期間不足、取引日1日欠落、重複日付 | `pending`。全体の日数が近くても合格にしない |
| 通貨不明、銘柄不一致、必須数値欠損、内容hash不一致 | 受入不可。読込・完全性検証に失敗した場合は技術エラー |
| 月末後の対象外市場への移行が既知 | `pending`。月次snapshotだけで合格にしない |
| 配当原通貨が未確認 | 価格証拠は制約付き受入可能。原通貨を必要とする計算は保留 |
| 旧期間の受入済みデータを、より新しい基準日の解析へ再利用 | 終端日と期間を再検証する。過去の受入状態だけで最新扱いしない |
