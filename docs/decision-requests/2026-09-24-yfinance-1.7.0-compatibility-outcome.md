# yfinance 1.7.0 compatibility判定

## 再評価結果（2026-09-25）

repository ownerは、`yfinance 1.7.0`がHTTP error時に行うcookie strategy切替と1回のstatus fallbackを許容した。
このため本書の不採用結論を撤回し、source approval v2とprofile v3で採用する。

- fallbackを含む全physical sendは注入sessionを通し、送信ごとにCoordinator permitを取得する。
- `YfConfig.network.retries`は0を維持し、transport exceptionへの一般的なretryは許可しない。
- `threads=False`、direct fallback禁止、cache無効、既存rate limitを維持する。
- cookie strategy切替以外の再送を新たに確認した場合はfail closedで再審査する。

以下は2026-09-24時点の旧判定として保持する。

## 結論

`yfinance==1.7.0`は、承認済みの`DEC-13`とsource profile v1の全条件を満たさないため採用しない。
dependencyは追加せず、最新profileである`yfinance-source-profile-v2`をdisabledとする。

この判定は、2026-09-24時点のPyPI最新安定版1.7.0をPython 3.14.2の隔離環境で実測した結果に基づく。

## Gate結果

| Gate | 結果 | 根拠 |
|---|---|---|
| Python 3.14 install/import | pass | Python 3.14.2でwheelと依存関係をinstallし、`yfinance.__version__ == "1.7.0"`を確認 |
| public session injection | pass | `yfinance.download(..., session=...)`が公開シグネチャに存在 |
| cookie/crumbを含む全send捕捉 | pass | `YfData`は注入sessionを保持し、cookie、crumb、consent、chart要求に同じsessionの`get`/`post`を使用 |
| `threads=False` | pass | `download`の公開引数で指定可能 |
| internal retry禁止 | fail | `_make_request`はHTTP status 400以上でcookie strategyを切り替え、設定値に関係なく同じrequest methodを再実行 |
| Coordinator境界での検証 | fail | 上記の自動再送を許容しない現行profileでは、公開APIだけで準拠した実行経路を構成できない |

## 不採用理由

`YfConfig.network.retries`の既定値は0であり、例外に対する指数backoff再試行は停止している。しかし、
`YfData._make_request`には別経路として、HTTP 4xx/5xxを受けるとcookie strategyを変更して必ず再送する処理がある。
この再送を無効化する公開設定は確認できなかった。

注入sessionで各physical sendを捕捉してCoordinator permitを取得する設計は可能だが、source approval/profileは
「自動再試行しない」と明示している。private APIのmonkey patchやvendoringで回避すると、承認済みの
「公開APIで証明できる固定版」という採用条件から外れる。このため、捕捉可能であることだけを理由に採用しない。

## 再評価条件

次のいずれかが成立した場合に、新しいcompatibility判定とprofile versionを作成する。

- upstreamの公開APIでHTTP status後のcookie-strategy再送を無効化できる。
- 再送を含む全physical sendのpermit取得を前提として、source approvalのfailure behaviorとprofileの
  `automatic_retry_allowed`を人が明示的に改訂する。
- `yfinance`を使わず、承認済みの公式または契約済みmarket-data sourceへ切り替える。

旧profile v1は履歴として保持するが、新規runtime選択では最新versionのv2を使用し、disabledとしてfail closedする。
