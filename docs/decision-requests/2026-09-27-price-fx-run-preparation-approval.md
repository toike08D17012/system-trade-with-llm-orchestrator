# 価格・FX証拠の通常実行準備への接続承認

2026-09-27、repository-ownerは価格・FX証拠を通常実行の準備工程へ接続する計画を承認した。
実装・検証・文書同期・コミットを対象とする。

## 承認した境界

- 確認時刻に必要なJPY価格の終端と、確定済みUTC FX日足の必要終端を分離する。
  証拠が欠けても必要日を過去へ繰り下げて成功させない。
- 立会終了後に取得した当日JPY価格は、通常実行用の品質判定で受入可能とする。
  UTC日足確定前の当日FXは未換算とし、JPY受入を取り消さない。
- 出典・hash・確認時刻付きローカルカレンダーを利用する。市場profile v2の適用期間は
  2026-09-27〜2026-12-26。カレンダーは必要開始日から確認日の東京日付までの収録を必須とする。
  profileの`known`は今回承認されたローカル予定表の利用方式を表し、
  新しいJPXデータの取得完了や実際の取引成立を表すものではない。
  カレンダー不足なら`pending`とし、休日を曜日だけから推測しない。
- 保存証拠を再検証して新しいtaskに関連付ける。原task・原bytes・hash・取得時設定を保持し、
  現在のsource承認に基づく再利用可否も確認する。
- yfinanceは既承認のnative history方針とapproval v3を使い、
  旧HTTP単位のprofile v3を新規経路の条件として復活させない。
- `PriceFxPreparationManifest`は価格・FX限定の内部形式である。
  凍結済み`EvidenceSetV1`や公開`ExecutionManifestV1`を代用せず、`analysis_ready=false`を維持する。
- `plan`・`prepare`・`validate`は通信しない。不足時は必要期間・理由を示し、
  自動取得・retry・バックフィル・BOJへのfallbackは追加しない。

## 互換性と制約

旧価格受入v1、BOJ v1、Dukascopy v2の証拠と再検証結果は変更しない。
現在日付への再評価は新しい準備directoryへ保存する。
当日価格の供給を含む取得工程の自動連携、財務・開示、全証拠集合の凍結、
Agent分析・レビューは後続作業である。

内部の`ready_with_limitations`は、保存された予定表と入力証拠に対する価格・FX準備の充足を示す。
providerへの訂正確認、最新の上場確認、詳細解析全体の鮮度確認を済ませたとの主張には使わない。
