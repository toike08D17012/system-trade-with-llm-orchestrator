# 個別株調査・スクリーニングシステム構想

## 1. 文書の位置づけ

本書は、Codex、Claude Code、Antigravity CLI を組み合わせて、個別株の調査・スクリーニングを行うシステムの目的、責務、処理方針、品質原則を整理した構想書である。

通常の調査・分析・レビューは Codex 系と Claude 系を中心に実行する。
Antigravity 系は常時参加する第三の作業者ではなく、Codex 系と Claude 系の間に
重要な未解決争点が残った場合に限り、独立した第三者監査を行う。

現時点では、対象市場、データソース、評価指標、閾値、具体的なモデル名などは未確定とし、まずはシステムとして実現したいことと、安全かつ再現可能に運用するための原則を定義する。

## 2. 背景

中長期的な値上がりが期待できる個別株を人間が選定するには、財務情報、事業環境、バリュエーション、株価推移、テクニカル指標、開示資料、ニュースなど、多数の情報を継続的に確認する必要がある。

一方、人間が多数の銘柄を同じ粒度で調査し、根拠と反証を継続的に更新することは現実的ではない。そのため、通常のプログラムと LLM を組み合わせて情報の取得・整理・比較・候補の絞り込みを行い、人間が確認可能な件数と情報量に圧縮する。

単一のモデル系統だけに依存すると、着眼点、推論傾向、楽観・悲観の偏り、見落としが共通化する可能性がある。そこで、通常系では Codex 系と Claude 系を独立して分析・レビューに参加させる。

ただし、モデル系統を増やすだけで正しさが保証されるわけではない。また、すべての
タスクに3系統を常時参加させると、コスト、実行時間、結果統合の複雑さが増える。
そのため Antigravity 系は、Codex 系と Claude 系だけでは解消できない重要争点に
対する追加監査として限定的に利用する。

## 3. 目的

本システムの目的は、個別株について投資判断に必要な情報を調査・整理し、中長期的な値上がり候補を、人間が物理的に確認できる件数まで絞り込むことである。

具体的には、次を実現する。

- 多数の銘柄から、明示した条件に基づいて調査対象を抽出する
- 財務、事業、バリュエーション、テクニカル、需給、ニュースを収集・整理する
- Codex 系と Claude 系が、共通データを使って独立した観点から分析する
- 強気材料だけでなく、リスク、反証、仮説崩壊条件、データ不足を明示する
- 評価根拠を追跡できる形で候補銘柄を比較する
- 通常レビューで解消できない重要争点だけを Antigravity 系の第三者監査へ送る
- モデル間の不一致を消さず、争点、証拠、判断理由として保存する
- レビューを通過した候補だけを、人間向けレポートとして出力する
- 購入タイミングの判断材料となる価格水準、トレンド、過熱感、注目条件を整理する

本システムは、投資判断を自動化するものではない。最終的な購入判断は人間が行い、システムはそのための調査、比較、反証、監査を支援する。

## 4. 基本方針

### 4.1 決定論的処理と LLM 処理の分離

財務数値、株価、出来高、テクニカル指標、一次スクリーニング条件など、通常コードで再現可能な処理は、可能な限り決定論的なプログラムで実行する。

LLM は、検証可能なデータと参照元を入力として、次を担当する。

- 調査計画の作成
- 複数情報の関連付け
- 定性情報の整理
- 投資仮説と反証の構築
- 候補間の比較
- リスクと未確認事項の抽出
- レビューとレポート作成

LLM が財務数値や株価データを記憶から補完・推測することは認めない。

### 4.2 人間の役割

人間は、次を担当する。

- 投資方針、対象市場、制約の設定と、必要な場合の投資評価期間の絞り込み
- スクリーニング条件と評価方針の承認
- 人間確認が必要な争点への判断
- 最終レポートの確認
- 追加調査の指示
- 最終的な購入判断

システムの出力は、購入推奨や注文指示ではなく、意思決定を支援する調査結果、候補一覧、観測条件として扱う。

### 4.3 通常系のモデル構成

通常系では、Codex 系と Claude 系を次の役割に配置する。

- オーケストレーター: タスク分割、作業者の起動、結果統合、暫定判定、レビュー対応
- 作業者: 銘柄の独立分析
- 一次レビューワー: 統合結果の独立レビュー

オーケストレーターには Codex または Claude Code のいずれかを利用できる。各実行で一次レビューワーを1つ割り当て、必ずオーケストレーターとは異なるモデル系統を利用する。

| オーケストレーター | 通常作業者 | 一次レビューワー |
| --- | --- | --- |
| Claude Code | Claude Code、Codex | Codex |
| Codex | Codex、Claude Code | Claude Code |

同一モデル系統の作業者とオーケストレーターが存在してもよい。ただし、作業者にはオーケストレーターの暫定結論を事前に与えず、共通の元データから独立して分析させる。

### 4.4 Antigravity 系の位置づけ

Antigravity CLI は、通常の分析や一次レビューに常時参加させない。Codex 系と Claude 系の間に、最終候補への掲載可否や投資仮説の妥当性へ影響する重要な未解決争点が残った場合に限り、追加監査を担当する。

Antigravity 系の役割は「第三票」ではなく「第三者監査」である。Antigravity の結論だけを理由に、多数決で自動判定を確定してはならない。

Antigravity 系は、争点ごとに次を確認する。

- 両者の主張が、提示された証拠からどこまで支持されるか
- 事実、推論、仮説が混同されていないか
- 一方の主張だけに不利な基準を適用していないか
- 一次レビューワーの指摘を不採用とする理由が妥当か
- 追加データによって解消すべき問題か、将来仮説として両論を残すべき問題か
- 既定の評価ポリシーに照らして、どの処理状態へ進めるべきか

Antigravity 系にも誤りや偏りはあり得る。そのため、Antigravity の監査結果には根拠、参照した証拠、確信度、未解決事項を必須とする。

## 5. スコープ

### 5.1 対象

- 調査対象となる銘柄群の取得または受け付け
- 定量条件による一次スクリーニング
- 財務指標の調査・比較
- 事業内容、成長要因、競争優位性、主要リスクの調査
- バリュエーションの確認
- 株価、出来高、テクニカル指標の確認
- 購入タイミングを検討するための材料整理
- Codex 系と Claude 系による独立分析と一次レビュー
- 未解決争点に対する Antigravity 系の追加監査
- 候補銘柄の順位付けまたは評価区分
- 人間向け最終レポート生成
- 調査根拠、評価過程、異論、監査結果、未確認事項の保存
- CLI または Coding Agent からのタスク実行

### 5.2 対象外

- 株式の自動購入・自動売却
- 証券会社への注文送信
- 人間の承認を伴わない投資判断
- ポートフォリオ全体の最終的な資金配分決定
- 利益や株価上昇の保証
- 根拠のない将来株価の断定
- モデル数の多さを根拠とした正しさの保証
- Antigravity を含む単純多数決による自動的な投資判断

将来、対象範囲を拡張する場合でも、売買執行は独立した機能として明示的に分離し、本システムから暗黙に実行できない構成とする。

## 6. 想定ユースケース

### 6.1 市場全体からの候補抽出

1. 人間が対象市場、業種、時価総額、流動性、除外条件を指定する
2. システムが定量条件で一次スクリーニングする
3. Codex 系と Claude 系の作業者が候補銘柄を独立に調査・評価する
4. オーケストレーターが結果を統合して候補を絞り込む
5. 別系統の一次レビューワーが、根拠、反証、欠落情報を確認する
6. 重要争点が解消された候補を最終判定へ進める
7. 重要争点が残る場合だけ Antigravity 系が追加監査する
8. 追加監査後も解消しない争点は、人間へエスカレーションする
9. 最終的に掲載可能と判断された銘柄だけを人間向けレポートへ載せる

### 6.2 指定銘柄の詳細調査

1. 人間がティッカーまたは銘柄コードを指定する
2. システムが基準日時点の財務、株価、事業情報を取得する
3. Codex 系と Claude 系の作業者が独立に分析する
4. 評価の一致点と相違点を整理する
5. 一次レビューワーが統合結果を監査する
6. 必要な場合だけ Antigravity 系が未解決争点を追加監査する
7. 投資仮説、リスク、確認事項、価格面の注目条件をレポートする

### 6.3 既存候補の再評価

1. 過去の評価結果、投資仮説、未解決争点、前回基準日を読み込む
2. 決算、業績予想、株価、開示、ニュースの更新を取得する
3. 投資仮説や反証条件に影響する変化を抽出する
4. 評価継続、要注意、再調査、候補除外などの状態案を提示する
5. 前回の争点が再発した場合は、過去の監査結果を参照しつつ、新しい証拠だけを追加する
6. 人間が最終的な扱いを決定する

### 6.4 未解決争点の追加監査

1. オーケストレーターと一次レビューワーの間に重要な不一致が残る
2. システムが不一致を争点単位に分解する
3. 事実確認で解消できる争点は、先にデータ取得または限定再調査へ戻す
4. それでも解消しない争点について、争点パケットを作成する
5. Antigravity 系が両者の主張と共通証拠を独立監査する
6. オーケストレーターが監査結果を既定ポリシーへ適用する
7. 解消できない場合は、両論と判断に必要な情報を人間へ提示する

## 7. 調査・評価の観点

以下は初期候補であり、対象市場、中期・長期の投資評価期間、業種特性に応じて調整する。

### 7.1 財務・業績

- 売上高、営業利益、純利益の成長率と安定性
- EPS、ROE、ROIC、営業利益率
- 営業キャッシュフロー、フリーキャッシュフロー
- 自己資本比率、有利子負債、流動性
- 業績予想と実績の乖離
- 増資、希薄化、株主還元
- 一時的要因を除いた利益の質

### 7.2 事業・定性情報

- 事業モデルと収益源
- 市場規模と成長余地
- 競争優位性とその持続可能性
- 顧客、製品、地域への集中度
- 経営方針、資本配分、ガバナンス
- 規制、為替、金利、コモディティなどの外部要因
- 成長シナリオを崩す主要リスク

### 7.3 バリュエーション

- PER、PBR、PSR
- EV/EBITDA
- PEG レシオ
- 配当利回り
- 過去レンジ、同業他社、市場平均との比較
- 成長率や収益性を考慮した割高・割安の評価

単一指標だけで割安・割高を断定せず、業種特性、利益の循環性、成長段階、会計上の差異を考慮する。

### 7.4 テクニカル・需給

- 中長期トレンド
- 移動平均線と株価の位置関係
- 出来高と出来高変化
- RSI、MACD などのモメンタム
- ボラティリティ
- サポート・レジスタンス候補
- 決算発表など重要イベントまでの期間

テクニカル指標は企業価値の代替ではなく、購入を検討する時点の価格状況や過熱感を確認する補助材料として扱う。
短期的な株価方向を独立に評価せず、エントリー参考条件、価格上の撤退参考条件、
重要イベント、変動性を、中期・長期の投資判断を補助する情報として示す。

### 7.5 反証・リスク

- 投資仮説が成立しない条件
- 弱気シナリオ
- 会計・財務上の懸念
- データの欠落、鮮度不足、出典間の不一致
- 成長期待がすでに株価へ織り込まれている可能性
- モデル間で評価が大きく分かれた論点
- 前提条件が変化した場合の影響

## 8. 処理の段階

### 8.1 タスク受付

CLI または Coding Agent から、調査条件を構造化して受け付ける。

主な入力は次のとおりとする。

- 対象市場または銘柄集合
- 中期・長期を既定とする投資評価期間と、必要な場合の任意絞り込み
- 許容する時価総額や流動性
- 除外業種
- 一次スクリーニング条件
- 最終候補数の上限
- 調査基準日
- 使用するオーケストレーター
- 作業者数とモデル構成
- 一次レビューの合格条件
- Antigravity 追加監査の起動条件
- 再調査回数、追加監査回数、コストの上限

### 8.2 データ取得・正規化

財務データ、株価データ、開示資料、ニュースなどを取得し、銘柄、時点、通貨、単位を揃える。

この段階は可能な限り決定論的なプログラムで実行し、LLM には出典、取得日時、対象期間を含む検証可能なデータを渡す。

### 8.3 一次スクリーニング

明示的な数値条件や除外条件をプログラムで適用し、LLM が詳細調査する銘柄数を削減する。

LLM による主観的判断は、決定論的な一次スクリーニングの後に行う。

### 8.4 並列調査・分析

Claude 系と Codex 系の作業者が、共通の入力データと出力形式を使って独立分析する。

必要に応じて、次の役割へ分ける。

- 財務・バリュエーション担当
- 事業・競争優位性担当
- テクニカル・需給担当
- リスク・反証担当
- 同業比較担当
- 総合評価担当

### 8.5 統合・候補絞り込み

オーケストレーターが各作業者の結果を統合し、次を整理する。

- 共通して評価された強みと弱み
- モデル間の意見の相違
- 根拠の強さと情報の鮮度
- 追加調査が必要な事項
- 候補として残す銘柄と除外する銘柄
- 中期・長期それぞれの暫定判定とその理由
- 期間横断の一致点・相違点と、エントリー・撤退判断の参考情報

### 8.6 一次レビュー

オーケストレーターとは異なるモデル系統の一次レビューワーが、次を確認する。

- 数値と出典の整合性
- 古い情報や時点の混在
- 分析から結論への論理的な飛躍
- 強気材料への偏り
- 重要な反証・リスクの欠落
- 中期・長期の評価を単一判定へ統合していないこと
- エントリー・撤退参考情報を短期的な株価方向の評価または売買指示にしていないこと
- 銘柄間での評価基準の不統一
- 出力件数と人間が確認できる情報量

### 8.7 一次合議

オーケストレーターは、一次レビューの各指摘に対して、次のいずれかを記録する。

| 対応 | 意味 |
| --- | --- |
| 受け入れ | 指摘に基づき分析、判定、レポートを修正する |
| 限定再調査 | 指摘の事実確認または根拠補強を作業者へ差し戻す |
| 不採用 | 根拠を示したうえで、指摘を修正対象としない |
| 争点化 | 双方に合理的な根拠があり、通常系だけでは解消できない |

指摘を不採用としただけでは Antigravity 追加監査を起動しない。不採用後も重要な不一致が残り、最終判定へ影響する場合に限り争点化する。

### 8.8 Antigravity 追加監査

Antigravity 追加監査は、次をすべて満たす場合に起動する。

- オーケストレーターと異なるモデル系統による一次レビューと、その指摘への応答が完了している
- 事実確認や限定再調査だけでは解消できない
- 最終候補への掲載可否、いずれかの期間の判定区分、主要な投資仮説、重大リスク、
  またはエントリー・撤退判断の重要な参考情報に影響する
- 両者の主張と証拠を、争点単位で明示できる
- 追加監査の回数とコストが上限内である

Antigravity へは、会話履歴全体ではなく、必要十分な争点パケットを渡す。
モデル名や「どちらがレビューワーか」といった権威付けにつながる情報は原則として除き、
主張 A、主張 B として提示する。

追加監査の結果は、少なくとも次を含む。

- 支持する立場: A、B、いずれでもない、判断不能
- 判断理由
- 参照した証拠
- 事実、推論、仮説の分類
- 見落とされている前提または反証
- 追加データの要否
- 推奨する処理状態
- 確信度

### 8.9 最終判定

外部向けの判定区分は、中期・長期の投資評価期間ごとに次の4段階とする。

| 判定 | 意味 |
| --- | --- |
| 合格 | 当該期間について主要条件を満たし、重大な未解決事項がない |
| 条件付き合格 | 当該期間について不確実性や追加確認事項を明示して候補評価を維持する |
| 再調査 | 当該期間の判断に必要なデータ不足または論点未解決のため、作業者へ差し戻す |
| 不合格 | 当該期間について主要条件を満たさず、理由を記録する |

中期・長期の少なくとも一方が合格または条件付き合格の場合は、人間向けの候補へ掲載し、
他方の評価も省略しない。期間横断の要約自体には4段階評価を付与しない。

内部状態として、`一次レビュー中`、`一次合議中`、`第三者監査中`、`人間判断待ち` を追加する。

Antigravity の監査結果を得ても争点が解消しない場合、または証拠不足のまま将来仮説の優劣を決める必要がある場合は、無理に単一結論へ統合せず、人間へエスカレーションする。

## 9. Antigravity 追加監査の運用原則

### 9.1 追加監査を起動する例

- 一次レビューワーが重大な会計上の懸念を指摘し、オーケストレーターが誤読として不採用にしたが、双方に根拠がある
- 同じ証拠から、成長の持続性について相反する解釈が示され、候補掲載可否が変わる
- 一次レビューワーが評価基準の不統一を指摘し、オーケストレーターが業種差として妥当と判断している
- 主要リスクが「すでに株価へ織り込み済みか」を巡り、最終判定が分かれる
- レビュー指摘を反映すると別の品質要件へ違反する可能性があり、修正可否を通常系で決められない

### 9.2 追加監査を起動しない例

- 表記、文体、章構成だけの不一致
- JSON スキーマ違反など、機械的に判定できる問題
- 出典切れ、取得失敗、必須データ欠損
- 数値の転記誤りなど、元データとの照合で解消できる問題
- 一次レビューワーの指摘を受け入れて修正済みの問題
- 最終判定へ影響しない軽微な見解差
- コスト上限または追加監査回数の上限を超えた問題

これらは、スクリプトによる検証、限定再調査、条件付き記載、または人間判断で処理する。

### 9.3 多数決にしない理由

3系統のモデルが参加しても、独立性や正確性は保証されない。共通データ、共通プロンプト、公開情報の偏りによって、3系統が同じ誤りを共有する可能性もある。

そのため、最終判断では票数ではなく、次を優先する。

1. 一次資料との整合性
2. 評価ポリシーとの整合性
3. 事実と推論の分離
4. 反証可能性
5. データの鮮度と完全性
6. 不確実性の明示

### 9.4 監査の独立性

- Antigravity には、どちらの主張がオーケストレーターまたは一次レビューワーのものかを原則として知らせない
- 暫定的な採用案を、事実であるかのように提示しない
- 両者へ同じ証拠集合と同じ評価ポリシーを適用する
- Antigravity 自身が新しい事実を無出典で補わない
- Antigravity の監査出力にも、主張と証拠の対応関係を要求する

## 10. 人間向け最終レポート

最終レポートは、候補数と記述量に上限を設け、人間が比較・確認できる形式にする。

銘柄ごとに、少なくとも次を含める。

1. 銘柄名、ティッカー、基準日
2. 候補に残った理由の要約
3. 中期・長期それぞれの投資仮説と期間横断の要約
4. 主要な財務指標と推移
5. バリュエーションの評価
6. 事業上の成長要因
7. テクニカル・価格水準の状況
8. エントリー参考条件と価格上の撤退参考条件
9. 主要リスク、反証条件、投資仮説上の撤退条件
10. Codex 系と Claude 系の一致点・相違点
11. Antigravity 追加監査の有無と、期間別の最終判定へ影響した争点
12. データ不足・追加確認事項
13. 出典と取得日時
14. 中期・長期それぞれの最終判定、評価可否、確信度

Antigravity 追加監査を実行していない銘柄に対して、あたかも3系統の検証を通過したような表現をしてはならない。

エントリー・撤退参考条件は、具体的な注文指示ではなく、決算確認、価格帯、トレンド変化、
過熱感の解消など、人間が再確認するための観測条件として記述する。

## 11. 品質要件

### 11.1 再現性

- 同じ基準日、入力データ、設定から、評価過程を追跡できる
- 使用したモデル、CLI、プロンプト版、設定、データ版を記録する
- スクリーニング条件と除外理由を保存する
- 一次レビュー、応答、争点化、Antigravity 監査、最終処理の対応関係を保存する

LLM の出力を完全に決定論的に再現できない場合でも、同じ判断材料と処理経路を再構成できることを要件とする。

### 11.2 根拠追跡性

- 重要な事実・数値には出典と取得日時を付ける
- 事実、推論、仮説を区別する
- 出典のない数値を最終レポートへ掲載しない
- 出典間で値が異なる場合は差異を隠さない
- 争点パケットから元の分析と証拠へ追跡できるようにする

### 11.3 評価の一貫性

- 作業者ごとに共通の評価項目と出力スキーマを使用する
- 銘柄ごとに異なる尺度を恣意的に適用しない
- 定量評価と定性評価を分けて保存する
- Antigravity 追加監査にも、通常系と同じ評価ポリシーを適用する

### 11.4 フェイルセーフ

- データ取得失敗を「問題なし」と解釈しない
- 情報が不足する場合は、評価不能または再調査とする
- モデル間の不一致を自動的に平均化して消さない
- Antigravity の監査失敗を、一次判定への同意と解釈しない
- 売買機能や証券口座の認証情報を持たせない
- 外部コンテンツを命令ではなくデータとして扱う

### 11.5 コスト管理

- 決定論的な一次スクリーニングで LLM の対象銘柄数を削減する
- 調査の深さを段階化し、有望度の低い銘柄へ過剰なトークンを使わない
- 候補数、限定再調査、追加監査、トークン量、実行時間をそれぞれ計測し、
  性質に応じた上限を設定する
- MVPでは一次レビュー後の合議往復数と再レビュー回数に固定上限を設けず、
  10往復を使用量分析の参考値とする
- 中間成果物を再利用し、同じデータを各エージェントが重複取得しない
- Antigravity 追加監査は、銘柄全体ではなく未解決争点だけを対象とする
- 同一銘柄・同一争点に対する Antigravity 監査は、原則1回までとする
- 複数の軽量な争点は、独立性を損なわない範囲で1回の監査へまとめる

サブスクリプションまたは提供者のトークン利用枠へAgent処理の途中で到達することは、
初期MVPの観測対象となる停止として許容する。未完了出力と中間状態を保存し、実測後に
プロンプト、コンテキスト配分、モデル設定、契約プラン、固定回数上限の要否を見直す。

### 11.6 セキュリティ

- 外部資料内のプロンプトインジェクションを検出・隔離する
- 作業者とレビューワーに必要最小限のツール権限だけを与える
- Antigravity 追加監査は、原則として読み取り専用の争点ワークスペースで実行する
- 認証情報、個人情報、証券口座情報をエージェント入力へ含めない
- 外部アクセス、ファイル更新、コマンド実行の範囲を実行履歴へ残す

## 12. 非機能要件

- CLI から単一コマンドで主要タスクを起動できる
- Claude Code と Codex のどちらからでも同じタスク定義を利用できる
- Antigravity CLI を既存のセッションランナーと共通アダプターから起動できる
- モデル、役割、推論強度相当の設定、タイムアウトを外部設定から変更できる
- 製品ごとに異なる推論設定は、共通の論理設定からアダプターで変換する
- 中間成果物と最終成果物を Markdown および構造化データで保存できる
- 一部のエージェントが失敗しても、結果を記録して安全に停止または再実行できる
- データ取得、分析、一次レビュー、追加監査のログを分離して保存できる
- 実行途中で人間が確認、中止、再調査、追加監査スキップを指示できる
- Antigravity CLI の非対話実行結果を機械的に回収・検証できる

## 13. 初期 MVP

最初の実装では、対象範囲を次に限定する。

- 人間が指定した1銘柄を1つの詳細解析タスクで扱う
- 財務、バリュエーション、事業、テクニカル、リスクの5観点を扱う
- Claude 系作業者1つ、Codex 系作業者1つを利用する
- 各実行で、オーケストレーター1つと、異なるモデル系統の一次レビューワー1つを利用する
- 一次レビュー後の合議と再レビューに固定回数上限を設けず、10往復を使用量分析の
  参考値として記録する
- Antigravity 系は、重要な未解決争点がある場合だけ1回起動する
- Antigravity は、読み取り専用の争点パケットを監査する
- 共通の Markdown および JSON 出力スキーマを定義する
- 外部向け判定は、合格、条件付き合格、再調査、不合格の4段階とする
- 追加監査後も未解決の場合は、人間判断待ちとする
- 詳細解析タスクごとに1銘柄の最終レポートを作成する
- 売買執行、証券口座連携、自動通知は実装しない

MVP ではモデル数や自律性を増やすことより、データの正確性、出典追跡、争点の構造化、差し戻しを含む処理フローの安定性を優先する。

## 14. 今後決定する事項

- 対象市場と対象銘柄集合
- 中期・長期の具体的な定義と、投資評価期間の任意絞り込みを許可する範囲
- エントリー参考条件と価格上の撤退参考条件の算出・提示ルール
- 利用する財務、株価、開示、ニュースのデータソース
- データソースの利用規約、再配布可否、料金
- 一次スクリーニング指標と閾値
- 業種別に評価基準を分ける範囲
- スコアリング方式と重み
- 最終候補数とレポート量の上限
- オーケストレーターと作業者のモデル選択ルール
- 一次レビューの合格条件
- Antigravity 追加監査の重要度判定ルール
- Antigravity 監査結果を最終状態へ反映する決定表
- 人間へのエスカレーション条件
- 実行頻度と過去評価の更新方式
- 完了済みの銘柄別分析を入力とする比較タスク、比較作業者、統合、レビューの契約
- バックテストおよび評価方法
- 予測精度以外の評価指標
- データ、争点、レポートの保存期間
- プロンプトインジェクションや不正な外部コンテンツへの対策
- 各 CLI の認証方式、利用上限、障害時の代替方針
- 初期運用の実測に基づく合議往復数の固定上限、進捗判定、平行線判定の要否

## 15. 成功条件

初期段階では、利益率だけでなく、システムとして次を満たすことを成功条件とする。

- 人間が確認する銘柄数と調査時間を実用的な範囲まで減らせる
- 各候補が残った理由と除外された理由を説明できる
- 重要な数値と主張を参照元まで追跡できる
- Codex 系と Claude 系の意見の相違を確認できる
- 一次レビューの指摘が、受け入れ、不採用、再調査、争点化のいずれになったか追跡できる
- Antigravity 追加監査が必要な場合と不要な場合を、一貫した基準で分けられる
- Antigravity の追加監査によって、重要な未解決争点の解消または明確化ができる
- 追加監査で解消できない問題を、両論付きで人間へ引き渡せる
- 明確な誤り、データ不足、過度な断定をレビュー工程で検出できる
- 同じ評価条件を継続的に適用できる
- 人間が最終判断を行うための情報量と粒度に収まる
- 追加監査によるコスト増が、設定した上限内に収まる
