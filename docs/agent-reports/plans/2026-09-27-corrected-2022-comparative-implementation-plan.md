# 訂正報告掲載の2022年比較値の限定採用

## 目的・検証済み根拠

S100RAR0掲載の2022年6指標を、原報告S100QZHYとの一致を条件に受入れ、既存24項目へ追加する。ユーザーの明確な次タスクの自動続行指示に基づく。追加の財務API取得は不要。

ローカル候補検査で2022・2023年の12組が原報告・訂正で一致し、2023年6組は既存2024年比較値とも一致した。2022-11-01版の公式schema2件を取得し、標準20宣言と6指標のtaxonomy関係を確認した。一般的な訂正選択や全文の意味照合を実装済みとは扱わない。

## 実装方針

既存`financial_disclosure.py`の訂正停止条件は維持する。新しい`financial_pair_acceptance.py`で固定した原報告・訂正pairを再検証し、訂正archive・proposal・公式schema根拠・期間に固定したpolicyで2022年6項目だけを採用する。既存`review_metric`、`adopt_metric`、taxonomy検証を再利用する。原報告との12組の一致を毎回検証し、不一致・nil・欠落で停止する。売上の原報告namespaceはpolicyで明示した対応だけを許可し、任意のlocal name置換はしない。

出典は訂正報告掲載値、報告期間は2022-04-01～2023-03-31、採用fact期間は2021-04-01～2022-03-31として分離する。訂正本文の定性的内容・最新性は未確認として保存する。pairの全依存hashと原報告の一致診断を残す。値はローカルのみ。

`financial_multi_report.py`とCLIへ任意のpair/pair-adoption入力を追加する。省略時は旧出力を維持する。指定時は全依存を再検証して、同じ5年窓に追加する。既存の値競合拒否を再利用し、出典別制約と時刻を保存する。

## 変更対象と手順

1. 新規固定policy・proposalを`config/financial-mapping/`へ追加。
2. 上記限定受入moduleとCLIを追加。既存受入関数を再利用。
3. 既存複数報告集約を拡張し、5/5期と分析可能性を区別する。
4. 対象テスト、実データprepare/replay、型検査・Ruff・全体hook、結果文書・コミット。

## 検証

原報告との不一致、policy・archive・出力改ざん、欠落・nil、期間混在、pair入力片方だけの指定を拒否する。実データは6項目の採用、統合30項目・5/5期、analysis_ready=falseを数値非表示で確認する。旧4/5期出力の再検証も維持する。

## 未解決事項

Blocking issuesなし。対象指標に競合がないため既存の限定採用方針を継続する。訂正全文の解釈、最新8 interim期間、IR・最新性の不足は残す。新しい不一致が出た場合は選択せず判断を求める。
