# 2023年原報告・訂正報告の限定取得

## 目的・承認

ユーザーは進行に必要な取得を許可し、間隔確保・不要な取得の抑制を指定した。今回は既存承認案のS100QZHYとS100RAR0のみ、最大2要求を実施する。追加承認待ちは不要。

## 実装

既存`edinet_evidence.py`の共有Coordinator・credential loader・raw保存・送信終了連携を再利用する。新規`edinet_pair.py`で固定hashの失敗一覧から対象2行だけを検証し、全体一覧を受入済みとは扱わない。原報告と訂正の発行体・種別・親ID・公開状態を確認する。新しい一回限りのcampaign markerと各送信slotを保存し、旧campaignを変更しない。

`config/source-approvals/edinet/v5.yaml`とprofileを追加し、既存bindingの固定hashに登録する。CLIに専用modeを追加する。2文書のrawと取得メタデータのみ保存し、通常財務受入は行わない。訂正の適用や2022年比較値の採用は取得後の調査で判断する。

## 検証

合成HTTPで最大2要求、60秒以上の間隔、再実行拒否、元一覧の改ざん・対象不一致・取得失敗を検証する。既存取得テスト、Ruff・Mypyを実施してから実通信する。取得結果は数値を表示せずdoc ID・hash・件数のみ確認し、結果を記録・コミットする。

## 制約

追加一覧取得・自動retryなし。旧v2～v4の挙動を変更しない。訂正前後の相違が重要な採用判断に影響する場合のみ人の判断を求める。Blocking issuesなし。
