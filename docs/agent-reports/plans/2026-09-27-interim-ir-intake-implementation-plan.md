# 四半期・半期IR資料の受入計画

## 根拠と目的

[候補調査](../research/2026-09-27-interim-source-inventory.md)で最新一覧・過年度一覧・最新短信1件を保存済み。年次5期は受入済み。次に、公表済み8期間の財務指標を、累計期間・金額単位・出典ページを保ってローカル受入する。

既存実装はEDINET XBRL向けで、IR PDF数値の受入器はない。最新PDFは全21ページのテキスト抽出が可能。損益・CFの前年同期欄と、財政状態表の前年度末欄を区別する必要がある。

## 必須指標の決定

要件02は8期間の対象を定めるが、各期の必須指標を列挙していない。次のどちらを必須とするかを確定する。

| 方針 | 必須範囲 | 現時点の取得候補 |
| --- | --- | --- |
| 推奨: 年次と同じ6指標 | 売上・営業利益・親会社帰属利益・資産・資本・営業CFを各期 | 8資料、うち最新1件取得済み |
| 損益・CF中心 | 前記のうち損益・CF4指標を各期、資産・資本は最新のみ | 比較欄を使う5資料候補、うち最新1件取得済み |

これは送信許可の再確認ではなく、取得対象と受入完了条件の仕様判断。比較欄にない資産・資本を推計したり、年末残高を四半期末へ代用したりしない。PDFごとの比較値・訂正・掲載範囲を確認し、想定と異なれば欠落を保持する。

## 判断後の実装方針

1. 明示した公式一覧のhash・実在リンクと期間を固定し、取得済み1件を再利用する。必要な残りだけを同時1・60秒以上の間隔・retryなしで取得する。原文はローカルのみ。
2. 新規IR PDF adapterを提案する。pypdf等の抽出方式をバージョン固定し、入力サイズ・ページ数・抽出資源を制限する。パスワードが必要なPDF・スキャンPDF・未対応レイアウトを推測で処理しない。
3. source・公表日・取得日・期間開始/終了・累計/時点・通貨/単位・連結範囲・ページ/表/行・元ファイルhashを各候補へ付ける。値の選択は決定的なルールとし、見出し競合・列順不明・単位不明・訂正不一致を拒否する。
4. 必須指標の確定に合わせて期間別coverageを実装し、年次との期間重複を明示する。年次5/5期、四半期・半期8期間、分析可能性を別々に保持する。
5. 合成PDF・抽出テキストで列入替・前年度末/前年同期混同・単位・nil/欠落・改ざん・サイズ上限を検証する。保存済み実資料は数値を出さずprepare/replayを行い、README・TODO・結果を更新してコミットする。

新規module・CLI・dependencyの正確な変更範囲は上記仕様判断後に確定する。既存XBRL受入・年次runは変更しない。

## 実装範囲の確定

2026-09-27の継続指示により、推奨した各期6指標を採用する。Blocking issuesなし。現物確認済みの最新1件と、公式一覧にある残り7件だけを使用する。

変更対象は`pyproject.toml`・`uv.lock`（pypdf 6.19.0の固定）、新規`sources/toyota_ir_pdf.py`（資源制限付き抽出・列/単位/期間検証）、新規`preparation/interim_ir.py`・同CLI（固定8期間のローカル受入、値とメタデータ分離、再検証）、対応テスト、要件02・README・結果文書。取得は既存のoperator取得証拠と同様にローカル保存し、公開runtimeのsource bindingが完成したとは扱わない。

PDFの金額はJPY百万単位を確認して円へ正規化する。損益・CFは期首からの累計、資産・資本は期末時点として別管理し、前年度末・前年同期の列を混同しない。未知のレイアウトや公表項目の欠落は未受入として保持する。既存の年次bundleとは別成果物とし、8期間の各6指標が揃ってもanalysis_ready=falseを維持する。

## Implementation Notes

8資料各6指標を採用した。残り7資料は各1回、最短62.96秒の間隔で取得し、最新1資料は再取得していない。
公開PDFの空パスワード暗号化は読取可能として許可するが、パスワード入力が必要なPDFは拒否する。
既存packageを読み込むworkerではメモリ制限の影響が生じたため、抽出だけを`_pdf_extract.py`の最小プロセスに分離した。
CPU・メモリ・サイズ・ページ・展開内容・テキスト・時間の制限を維持する。年月日や百万単位の文字間隔には対応するが、日付・単位・累計期間の意味の検証は維持する。

別成果物のprepare/replayで48項目・8/8期間を確認した。年次との接続は[後続計画](2026-09-28-interim-financial-run-implementation-plan.md)に従い、既存成果物を変更せず別bundleへ保存する。
