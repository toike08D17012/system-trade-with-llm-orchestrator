# ADR-0007: 汎用取得とLLM主導の不足情報判断を調査の基本経路とする

| 項目 | 値 |
| --- | --- |
| 状態 | Accepted |
| 決定日 | 2026-10-03 |
| 決定者 | リポジトリ所有者 |
| 適用範囲 | 指定銘柄の私的な詳細調査と追加資料取得 |
| 対応仕様 | [データソースと証拠の方針](../system-requirements/02-data-source-and-evidence-policy.md)の選定原則、公開資料の私的解析、再調査 |
| 実装状態 | Codex暫定調査、公開IRの1件取得、1件の再分析接続を内部CLIで実装。独立分析・汎用探索・最終レポートは未実装 |

## 背景

7203の財務、IR、品質リスクを調べる過程で、特定企業のPDF、URL、期間、資料一覧を
コードや設定へ固定し、完全な証拠集合を作ってからLLMを起動する作業が増えた。
この方法では、銘柄や調査時点が変わるたびに専用実装が必要になる。
所有者は、取得と数値加工をプログラムが担い、取得済み情報の解釈、不足情報の判断、
再調査の要否をLLMが担う運用へ変更するよう指示した。

## 決定

1. 指定銘柄について取得できた資料と定量データを出典付きでLLMへ渡し、LLMに暫定分析、
   不確実性、反証、追加取得依頼を返させる。初回から全項目が埋まっていることを
   調査開始条件にしない。情報不足は出力に残し、追加取得と再分析で扱う。
2. 取得時点の原本、URL、取得時刻、hash、採用した依頼と分析入力を保存する。
   時点の固定は再現性のために行い、その時点で資料が網羅的だったという主張には使わない。
3. 公開企業IRは企業別の固定parser・固定URL一覧・個別のLLM送信承認を必須としない。
   まず汎用の取得とテキスト抽出を使う。反復して必要な数値の機械集計など、明確な理由が
   ある場合だけ企業・形式固有の加工を追加する。既存の7203専用処理は履歴資料の検証に
   利用できるが、他銘柄の調査開始条件にしない。
4. リポジトリ所有者の私的解析に必要な公開資料・関連数値は、出典を明示して利用する。
   外部LLMへの処理目的の送信を、公開・再配布と同一視して一律に禁止しない。
   所有者はToyota等の企業IR、EDINET、JPX、Dukascopyの必要情報を私的LLM解析に
   用いる方針を示した。実際の取得・送信では、適用される利用条件、認証情報の保護、
   相手側への過負荷防止、成果物の非公開保存を守る。
5. 旧日本銀行FX取得経路は現行の鮮度要件に使わず、新規の取得実装から削除する。
   過去の試行結果と判断履歴は文書に残す。為替はDukascopyを使用する。

## 実装と残件の境界

現在の`preparation.research_draft`はCodexによる暫定分析を1回行う。
`preparation.research_follow_up`はローカル資料を前回の依頼へ結び付ける。
`preparation.public_ir_follow_up`は許可ホストの公開IRを1件取得し、
`preparation.research_step`はLLM候補から1件取得して再分析する。
これは公開IRの限定的な縦断経路であり、汎用Web探索、複数ソースの自動取得、
Codex・Claudeの独立分析、レビュー、最終判断まで完成したことを意味しない。

既存の公開IR取得経路の50 MB上限と、暫定分析入力の件数・本文長上限は、
[ADR-0006](0006-remove-source-response-capacity-limits.md)の容量上限撤廃方針との
整合確認が必要である。現状の実装制約として明示し、黙って承認済み方針を書き換えない。

## 採用理由と代替案

資料の網羅性や成長仮説を事前の固定リストと企業別parserだけで定義すると、
新しい銘柄・開示・リスクごとにコード変更が必要になる。LLMに不足を示させ、
検証済み資料を追加する方が調査の目的に合う。取得・数値加工と出典管理は
再現性が必要なため、引き続き決定論的な処理を使う。

全資料の収集完了までLLMを起動しない案は採用しない。LLMの提案URLを無条件に
自動取得する案も採用しない。候補URLには誤りや危険な接続先があり得るため、
許可ホスト、接続先確認、通信頻度制御を通す。

## 検証条件

- 別銘柄の調査開始に7203専用のコード変更を要求しない。
- 暫定分析が不足情報と追加取得依頼を保存し、取得原本と再分析入力の対応を再検証できる。
- 取得済み資料を私的LLM解析へ渡せる設定と、公開・再配布しない保存境界が一致する。
- 取得頻度と接続先の制御を守り、資料不足や取得失敗を分析完了と誤表示しない。
